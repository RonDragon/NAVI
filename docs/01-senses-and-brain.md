# איך ה-Navi יודע הכול — חושים ומוח

> השאלה: איך הוא ידע על הודעות, מיילים ושיחות, ישמע מה אני אומר,
> ואיך יהיה לו מנוע AI ש"יודע הכול"?

תשובה קצרה:
ה-Navi לא "יודע הכול" כי יש לו מודל-על.
הוא יודע כי יש לו **חושים** שאתה מאשר, **זיכרון** שמסנן ולומד,
ו**מוח** שמקבל בכל רגע רק את מה שרלוונטי.

```
 SENSES            PERCEPTION           CORE                BRAIN
 (inputs)          (filter)             (truth)             (LLM)
┌──────────┐     ┌──────────────┐     ┌──────────────┐    ┌──────────────┐
│Notifs    │     │ rules +      │     │ events       │    │ context      │
│Gmail     │ ──► │ small model: │ ──► │ memory       │ ─► │ builder      │
│Calendar  │     │ important?   │     │ follow-ups   │    │ (~8k tokens) │
│Calls meta│     │ about whom?  │     │ people       │    │   + tools    │
│Voice     │     │ needs action?│     │ personality  │    │ (search mail,│
│Location  │     └──────────────┘     └──────────────┘    │  calendar..) │
└──────────┘        95% dropped          canonical         └──────────────┘
```

## 1. החושים — מה באמת אפשר בכל פלטפורמה

זה החלק הכי חשוב להבין, כי הוא קובע איזה טלפון בונים קודם.

| חוש | Android | iPhone |
|---|---|---|
| **כל ההתראות** (WhatsApp, SMS, Telegram, מיילים, שיחות WhatsApp) | ✅ `NotificationListenerService`. המשתמש מאשר פעם אחת בהגדרות | ❌ אפליקציה לא יכולה לקרוא התראות של אפליקציות אחרות |
| **תוכן WhatsApp** | ✅ רק מה שמופיע בהתראה (טקסט ההודעה, השולח) | ❌ אין דרך. ל-WhatsApp אין API לחשבון אישי |
| **SMS** | ✅ דרך ההתראות (קריאה ישירה חסומה ב-Play Store) | ⚠️ חלקי, דרך Shortcuts automation ("כשמתקבלת הודעה") |
| **Gmail / Outlook** | ✅ דרך API בענן (Gmail API / Microsoft Graph) | ✅ אותו דבר, זה בענן ולא בטלפון |
| **יומן** | ✅ Google Calendar API / CalendarProvider | ✅ EventKit |
| **שיחות טלפון, מי ומתי** | ✅ call state + call log (באפליקציה שמותקנת ישירות, לא מ-Play) | ⚠️ רק "התחילה/הסתיימה שיחה" (`CXCallObserver`), בלי מספר |
| **תוכן שיחות (הקלטה)** | ❌ חסום מאנדרואיד 10, ולרוב גם לא חוקי בלי הסכמת הצד השני | ❌ |
| **"היי פיקסל", תמיד מקשיב** | ✅ foreground service + זיהוי מילת הפעלה על המכשיר. עולה סוללה, ורואים אייקון מיקרופון | ❌ רק כשהאפליקציה פתוחה, או דרך Siri/Action Button |
| **דיבור רגיל (לוחצים ומדברים)** | ✅ | ✅ |
| **מיקום (בית/עבודה)** | ✅ geofencing | ✅ geofencing |

### המסקנה

**החזון של NetNavi ("הוא רואה הכול ואיתי לכל דבר") אפשרי היום באנדרואיד. באייפון הוא אפשרי רק חלקית.**
Apple פשוט לא נותנת לאפליקציות לראות מה קורה באפליקציות אחרות.

ההמלצה שלי:
- **Android-first.** זה הטלפון שבו ה-Navi יכול להיות Navi אמיתי.
- **האפליקציה מותקנת ישירות (APK) בשלב הניסוי**, לא דרך Play Store.
  ככה אין את מגבלות המדיניות של Google על call log ו-SMS. זה חוקי לגמרי לשימוש אישי ולניסוי.
- **iPhone בשלב מאוחר יותר**, עם גרסה מצומצמת: מייל, יומן, קול, Shortcuts, והודעה אחרי כל שיחה.
- **מחשב (v0.2).** במחשב אפשר לראות הרבה יותר, כמו חלון פעיל וקבצים, וזה בית טבעי ל-Navi בשעות העבודה.

> ❓ **החלטה שצריך ממך:** איזה טלפון יש לך? אתה המשתמש הראשון, וזה קובע מאיפה מתחילים.

### שיחות טלפון — איך בלי להקליט

הוא לא מקליט שיחות. הוא יודע שהייתה שיחה ועם מי (באנדרואיד), ושואל אחריה:
"דיברת עם יוסי. יש משהו שכדאי שאזכור?"
ככה אתה נשאר בשליטה, ואין בעיה משפטית (מוקאפ 5).

### הקשבה

שלוש רמות, ואתה בוחר:
1. **לוחצים ומדברים.** ברירת המחדל.
2. **"היי פיקסל".** מילת הפעלה שמזוהה על המכשיר, ורק אחריה הקול יוצא לענן. אנדרואיד בלבד.
3. **תמיד מקשיב.** לא ב-MVP. זה גם מסוכן לפרטיות וגם שורף סוללה.

דיבור לטקסט בעברית: Whisper שאומן על עברית (יש מודלים פתוחים של ivrit.ai), או Google STT (`he-IL`).
קול עברי ל-Navi (TTS) הוא הסיכון הטכני הגדול, כי טקסט עברי כתוב בלי ניקוד. לכן זה נבדק מוקדם, ב-spike נפרד.

## 2. הסינון — למה הוא לא מוצף

ביום רגיל מגיעות לטלפון 100–300 התראות.
אם כל אחת תלך ל-LLM גדול, זה יקר, איטי, ולא פרטי.

לכן כל אות עובר **Perception** קודם:

```
notification arrives
   │
   ├─ rules (on device):  group chat? promo? known spam app?  → drop
   │
   ├─ small/cheap model:  from whom? about what? urgent? needs reply?
   │                      matches a pending follow-up? ("Danny's document")
   │
   └─ result:  DROP  |  DIGEST (show later)  |  NOW (worth interrupting)
                            │                      │
                            └──── event ───────────┘──► Core (memory candidates)
```

- **95% נזרקים** או נכנסים לסיכום בלי לעניין אף אחד.
- התראה גולמית נשמרת לכמה ימים בלבד. רק מה שחשוב הופך לזיכרון.
- "דני שלח את המסמך" מקבל חשיבות גבוהה, כי ה-Core יודע שחיכית לזה (Follow-up פתוח).
  **ככה נוצרת ההרגשה ש"הוא מבין אותי".** זה לא קסם של המודל, זה החיבור לזיכרון.

## 3. המוח — "מנוע שיודע הכול"

### מה הוא *לא*
- **לא מאמנים מודל משלנו.** אין צורך, זה יקר, וזה מתיישן מהר.
- **לא זורקים את כל ההיסטוריה ל-prompt.** זה יקר, וגם מחמיר את התשובות (context rot).
- **לא "מודל אחד".** המוח הוא תזמור של כמה מודלים.

### מה הוא *כן*
ה-Navi יודע דברים בשלוש דרכים:

| דרך | מה זה | דוגמה |
|---|---|---|
| **זרם (Stream)** | אירועים שנכנסים דרך החושים ועוברים סינון | "אמא התקשרה פעמיים" |
| **חיפוש (Look up)** | כלים שהמוח מפעיל רק כשצריך | "מה הבנק כתב לי?" ← חיפוש ב-Gmail עכשיו |
| **למידה (Learn)** | הלילה (ואחרי רצף אירועים חשובים) אירועים הופכים לעובדות והרגלים | "מעדיף להתאמן בערב" |

בכל פנייה, ה-**Context Builder** מרכיב חבילה קטנה (~8k tokens):

```
Navi core rules + personality envelope      ~1.8k
current state (emotion, time, what's today) ~0.5k
relationship + open follow-ups              ~0.5k
recent conversation                         ~2k
retrieved memories (score = recency+importance+relevance) ~2.5k
tool/capability context                     ~1k
```

והמוח יכול לקרוא לכלים:

```ts
searchEmail(query)        getCalendar(range)      recallMemory(query)
getRecentNotifications()  createReminder(...)     draftMessage(...)   // draft only, you send
```

זה בדיוק מה שעושה אותו "יודע הכול": **הוא לא זוכר הכול, אבל הוא יודע איפה לחפש, ויודע מה חשוב לך.**

### אילו מודלים

| תפקיד | מודל | הערה |
|---|---|---|
| שיחה רגילה | מודל בינוני ומהיר (Claude Sonnet / GPT mini) | רוב התנועה |
| סינון התראות, חילוץ זיכרונות | מודל קטן וזול (Claude Haiku / GPT nano) | הרבה קריאות |
| חשיבה קשה, קוד, תכנון | מודל גדול | רק כשצריך |
| דיבור לטקסט | Whisper-he / Google STT | |
| embeddings | כל ספק | בשביל retrieval |

הכול מאחורי `ModelRouter`, כדי שאפשר להחליף ספק בלי שה-Navi "יהפוך למישהו אחר".

## 4. פרטיות — כי הוא רואה הרבה

- כל חוש = הרשאה נפרדת, עם רמה: **רואה / מציע / פועל** (מוקאפ 6).
- **הוא אף פעם לא שולח הודעה או מייל לבד** ב-v0.1. הוא רק מכין טיוטה.
- סיסמאות וקודי אימות (OTP) לא נכנסים לזיכרון לעולם. מזהים אותם ומוחקים.
- מסך **"מה פיקסל יודע עליך"**: כל עובדה, מאיפה הוא למד אותה, תיקון ומחיקה (מוקאפ 7).
- התראות גולמיות נמחקות אחרי 7 ימים.

## 5. מה זה אומר על סדר הבנייה

צוות: **אתה + Claude + GPT.**
- **אתה:** מחליט, משתמש יומיומי ראשון, והשופט של "האם זה מרגיש חי".
- **Claude:** בונה את הקוד, הבדיקות והתשתית.
- **GPT:** חוות דעת שנייה על עיצוב ומוצר, ובודק את התוכניות.

הצעה לשלבים (כל שלב = משהו שאתה משתמש בו בעצמך):

1. **שלב 0, "הוא מדבר וזוכר"** (שבוע–שבועיים)
   אפליקציית אנדרואיד + backend. Awakening, שיחה בעברית, זיכרון, follow-up אחד שעובד מקצה לקצה.
2. **שלב 1, "הוא רואה"**
   חוש התראות + סינון + סיכום ("בזמן שהיית בפגישה"). יומן.
3. **שלב 2, "הוא שומע"**
   לוחצים ומדברים בעברית, סיכום אחרי שיחה, Gmail.
4. **שלב 3, "הוא חי"**
   הדמות ב-Rive, החדר שלו, Off-screen life, רגעי חברות.
5. **שלב 4:** 5–10 חברים משתמשים חודש. בודקים: "האם הוא מרגיש כמו חבר שבצד שלך?"
